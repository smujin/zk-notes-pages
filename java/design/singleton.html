单例模式

1. 什么是单例模式？

单例模式 是一种创建型设计模式，它确保一个类只有一个实例，并提供一个全局访问点来获取这个实例。

核心思想：

  • 私有化构造器：防止外部通过 new 关键字随意创建对象。
  • 静态私有实例：在类内部持有这个唯一的实例。
  • 静态公有方法：提供一个公共的、静态的方法，让外部能够获取到这个唯一的实例。

2. 为什么要使用单例模式？

单例模式通常用于管理共享资源，或者那些从逻辑上只需要一个对象的场景，例如：

  • 数据库连接池
  • 日志记录器
  • 应用配置信息
  • 线程池
  • 缓存系统
  • Spring 框架中默认创建的 Bean 就是单例的。

使用单例可以避免重复创建对象，节省系统资源，并提供一个统一的访问入口。

3. 单例模式的几种实现方式

单例模式的实现有多种，各有优缺点，主要区别在于线程安全性、懒加载和性能。

方式一：饿汉式

这种方式在类加载时就完成了实例化，避免了多线程同步问题。

public class SingletonEager {
    // 1. 静态私有实例，在类加载时即被创建
    private static final SingletonEager INSTANCE = new SingletonEager();

    // 2. 私有构造器，防止外部实例化
    private SingletonEager() {
        // 防止通过反射调用构造器
        if (INSTANCE != null) {
            throw new RuntimeException("单例对象不能重复创建");
        }
    }

    // 3. 公共的静态方法，返回唯一实例
    public static SingletonEager getInstance() {
        return INSTANCE;
    }
}

优点：

  • 实现简单，线程安全。
  • 获取实例速度快。

缺点：

  • 不是懒加载，如果这个类从未被使用，会造成内存浪费。

方式二：双重检查锁

结合了懒汉式的懒加载和高效同步的优点。

public class SingletonDCL {
    // 使用 volatile 关键字禁止指令重排序，确保多线程环境下的可见性
    private static volatile SingletonDCL instance;

    private SingletonDCL() {}

    public static SingletonDCL getInstance() {
        // 第一次检查，避免不必要的同步
        if (instance == null) {
            // 同步代码块
            synchronized (SingletonDCL.class) {
                // 第二次检查，确保实例在同步块内未被其他线程创建
                if (instance == null) {
                    instance = new SingletonDCL();
                }
            }
        }
        return instance;
    }
}

优点：

  • 线程安全。
  • 懒加载。
  • 只有在第一次创建实例时才同步，后续调用性能高。

注意： volatile 关键字在这里至关重要，它可以防止 instance = new SingletonDCL(); 这行代码的指令重排序，确保其他线程不会拿到一个未初始化完成的对象。

方式三：静态内部类

这是《Effective Java》推荐的一种实现方式，它利用了 Java 虚拟机的类加载机制来保证初始化实例时只有一个线程。

public class SingletonInnerClass {
    private SingletonInnerClass() {}

    // 静态内部类
    private static class SingletonHolder {
        private static final SingletonInnerClass INSTANCE = new SingletonInnerClass();
    }

    public static SingletonInnerClass getInstance() {
        // 只有当调用此方法时，SingletonHolder 才会被加载，INSTANCE 才会被初始化
        return SingletonHolder.INSTANCE;
    }
}

优点：

  • 线程安全（由 JVM 保证）。
  • 懒加载（只有在调用 getInstance() 时内部类才会被加载）。
  • 实现简洁，无需同步，性能高。

这是最推荐的一种实现方式。

方式四：枚举

同样是《Effective Java》强烈推荐的方式。它不仅能避免多线程同步问题，还能防止反序列化重新创建新的对象，以及防止反射攻击。

public enum SingletonEnum {
    INSTANCE; // 这就是单例的实例

    // 可以添加任意的方法
    public void doSomething() {
        System.out.println("枚举单例的方法执行了");
    }
}

// 使用方式：
// SingletonEnum instance = SingletonEnum.INSTANCE;
// instance.doSomething();

优点：

  • 实现极其简单。
  • 线程安全。
  • 防止反射和反序列化破坏单例。

这是实现单例的最佳实践。

4. 如何破坏单例及防御

除了枚举单例，其他方式都可能通过反射或反序列化被破坏。

  • 反射防御：在私有构造器中检查实例是否已存在，如果存在则抛出异常（如饿汉式示例所示）。
  • 反序列化防御：实现 Serializable 接口，并添加 readResolve() 方法，返回已有的实例。
    protected Object readResolve() {
    return getInstance(); // 返回单例实例，而不是反序列化生成的新对象
}

总结

建议：

  • 如果需要懒加载，并且不担心反射和反序列化，优先使用静态内部类。
  • 如果追求绝对的安全和简洁，强烈推荐使用枚举。
